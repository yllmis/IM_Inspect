# Trace 查询与错误回放

## 接口

- `GET /api/traces/{runId}`：返回经过权限校验和字段投影的 Trace 查询视图。
- `GET /api/traces/{runId}/replay`：返回只读错误回放视图。

两个接口都要求服务端认证，并按 `tenantId + actorId + runId` 查找，不能通过请求体伪造租户或操作者。

查询视图包含：

- 工具名称、参数摘要、结果摘要；
- 尝试次数、重试延迟、缓存命中、超时和截断标记；
- 继续或停止的确定性解释；
- 最终分类、人工确认状态和不支持的 Connector 能力。

## 回放边界

回放使用已经保存的 Trace 重建解释，不调用模型、Connector、数据库写操作或升级单接口。它可以说明“哪一步超时”和“为什么停止”，不能把旧的超时结果重新当作当前事实，也不能重新执行危险操作。

## MVP 存储边界

当前 `TraceStore` 使用有上限的进程内实现，适合本地开发和单实例演示。进程重启或多实例部署不会共享 Trace。`TraceStore` 接口已隔离，生产部署时可替换为 MySQL Repository，不需要改查询和回放逻辑。
